# Анализ лояльности пользователей Яндекс Афиши

Исследовательский анализ данных (EDA) о поведении пользователей сервиса
Яндекс Афиша с целью выявить факторы, влияющие на возврат клиентов
и совершение повторных покупок.

**Автор:** Спиридонов И. В.
**Дата:** 2026

---

## Цель проекта

Помочь команде маркетинга Яндекс Афиши понять, какие пользователи
с большей вероятностью возвращаются на платформу и совершают повторные
покупки. Это позволит точнее настраивать рекламу, оптимизировать
бюджеты и повышать уровень удержания (Retention Rate).

## Задачи

1. Загрузить данные из базы PostgreSQL `data-analyst-afisha` (схема `afisha`).
2. Провести предобработку: привести валюту к рублям, обработать пропуски,
   выбросы и дубликаты.
3. Построить профиль пользователя с агрегированными признаками.
4. Создать бинарные признаки `is_two` (2+ заказа) и `is_five` (5+ заказов).
5. Провести EDA и проверить гипотезы о влиянии типа мероприятия, региона
   и устройства на возврат.
6. Сформулировать выводы и рекомендации для бизнеса.

## Данные

- **Источник:** база PostgreSQL `data-analyst-afisha`, схема `afisha`
  (таблицы `purchases`, `events`, `city`, `regions`).
- **Период:** июнь–октябрь 2024 года.
- **Объём:** 290 611 заказов в исходной выгрузке.
- **Итог после очистки:** **287 326 заказов** и **21 698 уникальных
  пользователей**.
- **Дополнительный файл:** `final_tickets_tengge_df.csv` — курсы тенге
  для приведения выручки к рублям.

### Основные поля датафрейма

| Поле | Описание |
|------|----------|
| `user_id` | Уникальный идентификатор пользователя |
| `device_type_canonical` | Тип устройства (mobile, desktop) |
| `order_id` | Уникальный идентификатор заказа |
| `order_dt` / `order_ts` | Дата и дата-время создания заказа |
| `currency_code` | Валюта оплаты (rub, kzt) |
| `revenue` / `revenue_rub` | Выручка в исходной валюте / в рублях |
| `tickets_count` | Количество билетов в заказе |
| `days_since_prev` | Дней с предыдущей покупки (NULL для первой) |
| `event_id` / `event_name` / `event_type_main` | Данные о мероприятии |
| `service_name` | Билетный оператор |
| `region_name` / `city_name` | Регион и город |

> Данные анонимизированы: названия регионов, городов и операторов
> могут выглядеть необычно.

## Как запустить

1. Клонировать репозиторий:

   ```bash
   git clone https://github.com/DigitalOcean78/afisha-loyalty-analysis.git
   cd afisha-loyalty-analysis
   ```

2. Установить зависимости:

   ```bash
   pip install -r requirements.txt
   ```

3. Создать файл `.env` в корне проекта с параметрами подключения к БД:

   ```text
   DB_USER=your_user
   DB_PWD=your_password
   DB_HOST=your_host
   DB_PORT=5432
   DB_NAME=data-analyst-afisha
   ```

4. Открыть ноутбук:

   ```bash
   jupyter notebook
   ```

   и выполнить ячейки `DS_2_project _24.09.26.ipynb` сверху вниз.

## Ключевые результаты

### Лояльность аудитории

- **61.43%** пользователей совершили **2+ заказа**.
- **28.45%** — **5+ заказов**.
- Аудитория Яндекс Афиши — **высоколояльная**, почти две трети возвращаются.

### «Точки входа» — что влияет на возврат

| Признак первого заказа | Лучшие сегменты | Худшие сегменты |
|---|---|---|
| **Тип мероприятия** | Выставки (63.8%), театр (63.5%), концерты (62.1%) | Спорт (55.8%), ёлки (54.7%) |
| **Устройство** | Desktop (63.9%) | Mobile (60.9%) |
| **Регион** | Шанырский (68.5%), Светополянский (65.8%) | Малиновоярский (56.1%), Озернинский (55.0%) |
| **Оператор** | Край билетов (65.2%), Дом культуры (64.6%) | Билеты без проблем (60.4%) |

### Выручка, билеты и частота покупок

- **Медиана чека:** у вернувшихся (2+) — **506 руб.**, у «одноразовых» — **382 руб.**
- **«Золотой сегмент» — 2–3 билета:** доля вернувшихся **73.5%**.
- **«Аномальный сегмент» — 5+ билетов:** доля вернувшихся всего **19.3%**
  (корпоративные или разовые покупатели).
- **Интервал между заказами:** супер-лояльные (5+) покупают в **2 раза
  чаще** — среднее 10 дней против 21, поведение стабильнее
  (std 7.8 vs 28.6).

### Корреляционный анализ (phik)

Самые сильные связи с `total_orders`:

| Признак | phik |
|---|---|
| `avg_days_since_prev` | **0.28** |
| `avg_tickets_count` | **0.25** |
| `first_region` | 0.12 |
| `first_order_weekday` | 0.06 |
| `first_service` / `first_device` / `first_event_type` | 0.03 |
| `avg_revenue_rub` | **0.00** |

**Вывод:** ключевые предикторы лояльности — **частота покупок** и
**количество билетов**, а не сумма чека.

## Рекомендации для бизнеса

1. **Приоритетные сегменты для удержания:**
   - Пользователи, покупающие **2–3 билета** (самая лояльная аудитория).
   - **Desktop-пользователи** — сделать десктопную версию максимально
     удобной и стимулировать регистрацию с ПК.

2. **Работа с «точками входа»:**
   - Усилить маркетинг на **выставках, театре, концертах**, а также в
     **Шанырском** и **Светополянском** регионах.
   - Разобраться с провальными сегментами: **спорт**, регионы
     **Малиновоярский** и **Озернинский**, крупный оператор
     **Билеты без проблем**.

3. **Стимулировать частоту покупок:**
   - Push- и email-напоминания о новых событиях.
   - Программа лояльности или бонусы за частые покупки.
   - Перевод пользователей из группы «2–4 заказа» в «5+».

4. **Не ориентироваться на чек:**
   - Средняя выручка не влияет на возврат (phik = 0.00).
   - Фокус — на **частоте** и **количестве билетов**.

5. **Что требует дополнительных исследований:**
   - Аномально низкая возвращаемость в сегменте **5+ билетов** (19.3%).
   - Разница в лояльности между **mobile** и **desktop**.
